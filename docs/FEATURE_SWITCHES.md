# Feature switches

Every switch is a plain on/off value in `wrangler.toml`. Changing one needs a deploy from main (with the usual backup first).
All of them only show or hide things, EXCEPT `LATE_FEES` and `LATE_FEE_SPLIT`, the two switches that change money (see their rows). Last updated Wed Nov 4, 2026.

## Notes
- `ADMIN_R3` "on for everyone" is one `task_log` row (task `admin_r3_on`, no schema change), like the others. A backup restore empties `task_log`, so check this switch after a restore. The two switches it moves in Settings (`PAY_ALWAYS` row "Ask for payment on every game", `TIME_SHIFT` row "Moved-game notice for everyone") keep their own saved values and endpoints: only where the row is shown changes, and with `ADMIN_R3` off they show where they always did. With round 3 on, Alerts has one button, "Test smart alert" (it sends the smart-alert test message; Telegram must be connected).
- `LATE_FEES` "on for everyone" is one `task_log` row (task `late_fees_on`, no schema change). A backup restore empties `task_log`, so the switch is OFF after a restore; the debts themselves live on the seat rows (`session_players`: `played = 0` on a seat that left, `late_drop_at` equal to the finalize time for a no-show, `sessions.canceled_by = 'organizer_fee_kept'` for a late cancel) and come back with the restore, as of the backup. A Clear or a Venmo payment after the backup is lost, so check Venmo against Money after any restore. The health check `info_open_late_fees` counts open debts (a to-do, not a problem).
- `ADMIN_R2` "on for everyone" is one `task_log` row (task `admin_r2_on`, no schema change), like the other switches. A backup restore empties `task_log`, so check this switch after a restore. "Hide player" is one `task_log` row per hidden player (task `admin_hidden_player:<player id>`, no game): it only takes a name off the organizer's Players list and pickers (View as, Add someone); every seat, payment, credit and history row is untouched, and the player still works on their own screen. A restore (or `ADMIN_R2 = "off"`) only makes hidden names show again. Unhide (Settings > Advanced > Hidden players) always works.
- Anything other than `"on"` counts as off (for `TIME_SHIFT`, `PAY_ALWAYS`, `ADMIN_V2` and `PAY_NOTE`, anything other than `"off"` counts as on: those are kill switches, and who sees them is a Settings switch).
- The `[env.preview.vars]` block holds the same switches for preview links, which use the fake database. Production only reads `[vars]`.
- The private test links only work while the switch is off for everyone. Once it is on, they change nothing.
- Quiet windows for switching one on: Wed 6:00 AM to 6:00 PM, and Fri through Mon 6:00 PM (see SITE_RULES). Never in the hour after Alex texts the group.
- Quickest rollback for the motion switches: set the value to `"off"` and deploy (no data restore needed). Rollbacks are listed per deploy in `STAGE_NOTES.md`.
- `ADMIN_V2` "on for everyone" is one `task_log` row (task `admin_v2_on`, no schema change), like `PAY_ALWAYS`. A backup restore empties `task_log`, so check this switch after a restore. The motion fix (no rise on load, placeholder cards while loading) is not behind `ADMIN_V2`: it follows `MOTION_ADMIN`.
- `ADMIN_V2` also gates "Remove from player screen": it hides a CANCELED game from players with one `task_log` row (task `hidden_from_players`, that game's id). Nothing else is touched, the organizer still sees the game. Kill switch `ADMIN_V2 = "off"` puts every hidden game back on the player screen. Reopening a game clears the hide.
- `PAY_NOTE` "on for everyone" is one `task_log` row (task `pay_note_on`, no schema change), like `PAY_ALWAYS` and `ADMIN_V2`. A backup restore empties `task_log`, so check this switch after a restore.
- `PLAYER_FIX1` "on for everyone" is one `task_log` row (task `player_fix1_on`, no schema change), like `PAY_NOTE`. A backup restore empties `task_log`, so check this switch after a restore. Anything other than `"off"` counts as allowed (a kill switch); who sees it is the Settings switch or the private link.
- `PAY_SHEET` "on for everyone" is one `task_log` row (task `pay_sheet_on`, no schema change), like `PAY_NOTE`; a backup restore empties `task_log`, so check this switch after a restore. The Apple Pay / Zelle number is the `zelleNumber` key in `groups.settings_json` (absent = the default 248-247-9231, saved blank = `""` = no line); a backup restore brings it back as of the backup.
- `TEXTS_R2` "on for everyone" is one `task_log` row (task `texts_r2_on`, no schema change), like `PLAYER_FIX1`; a backup restore empties `task_log`, so check this switch after a restore. The 5-minute clock reads that row in the same database trip it already makes (no extra trip), so there is nothing else to deploy: the clock Worker (`worker/cron.ts`) is unchanged and only knocks. Alerts already sent stay sent (an alert is sent once per game, whichever wording was live).
- `LATE_FEE_SPLIT` "on for everyone" is one `task_log` row (task `late_fee_split_on`, no schema change), like `LATE_FEES`. A backup restore empties `task_log`, so the switch is OFF after a restore; a game already canceled with the split keeps its price (on the `sessions` row) and the credit it gave back (in `credit_ledger`), as of the backup. The cancel only goes ahead if no seat or credit on that game changed since it was read (the same check Finalize makes); otherwise it says "This game just changed. Look again." and nothing moves.
